# Structure and maintainability audit

Date: 2026-10-20. Static review of tracked source, build configuration, contributor guidance, and representative backend/frontend workflows. Findings describe observed code and potential consequences; this is not an exhaustive correctness or security assessment. No builds or tests were run for this documentation-only review. The August audit's test results are historical, not revalidated here.

## Overall assessment

The project has a useful layered foundation: `cmd` composes the server, `web` delivers HTTP/templates, `internal/app` owns application behavior, and `internal/store` owns persistence. SQLC, templ, strict TypeScript, scoped contributor instructions, and 65 Go test files provide a reasonable base. Feature packages such as `reader`, `tags`, and `userdata` show a practical direction for growth.

The main maintenance risk is uneven enforcement of those boundaries. Old and new patterns coexist, ownership is sometimes ambiguous, and several concrete reliability defects hide inside broad services. Improve incrementally around workflows; a repository-wide folder reshuffle would add churn without resolving the coupling.

## Findings, in priority order

| Priority | Finding and evidence | Recommended action |
| --- | --- | --- |
| High | **Authorization is inconsistent at the service boundary.** `TrashBook` and `UntrashBook` in [book_manager_impl.go](../../internal/app/book_manager_impl.go) accept commands containing `ActorUserID`, but ignore it and explicitly leave authorization as TODOs. This makes correctness depend on every caller applying equivalent policy. | Enforce ownership/role policy inside these methods and add cross-user regression tests. Assess HTTP exploitability separately; login alone is not ownership authorization. |
| High | **The recalculation worker has lifecycle and batching defects.** [book_background_service.go](../../internal/app/book_background_service.go) checks `running` and sends without the mutex used by `Stop`, which closes the channel; shutdown does not wait on its wait group. Batch deadlines are checked only after receiving another item, and pending items are not flushed on close. Timeout cancellation is deferred inside the long-running loop. | Use synchronized enqueue/shutdown, a timer-driven batch loop, explicit draining/waiting, and immediate per-operation cancellation. Test idle batches and concurrent shutdown. |
| High | **Search indexing duplicates mapping and uses unmanaged asynchronous work.** [book_search_reindex_impl.go](../../internal/app/book_search_reindex_impl.go) starts detached goroutines, discards a deadline cancel function, and logs failures without retry. Single and bulk indexing construct different document fields; full rebuild deletes the live index first and ignores bulk item-level results. | Share one document mapper, use a lifecycle-managed durable queue, inspect bulk results, and rebuild through a replacement index/alias. |
| High | **Error handling exposes internals and lacks one consistent boundary.** [recovery_middleware.go](../../internal/olhttp/recovery_middleware.go) writes stack traces to clients without setting a 500 status. [json_response.go](../../internal/olhttp/json_response.go) exposes `err.Error()`; public helpers map application errors broadly to 409. | Centralize typed error-to-status mapping and public error envelopes; log internal details with request IDs. Cover panic and partially written responses. |
| Medium | **Root `app` remains a large dependency hub.** [fx.go](../../internal/app/fx.go) wires many domains, while [book_manager_impl.go](../../internal/app/book_manager_impl.go) exceeds 1,000 lines and combines authoring, chapters, storage, and persistence. Compatibility aliases preserve old imports, so folder extraction alone does not remove coupling. | Follow the existing [package boundary plan](../development/application-packages.md): extract by ownership only after defining narrow neighbor contracts. Migrate touched callers to owning packages and retire bridges when unused. |
| Medium | **Persistence conventions have undocumented exceptions.** Contributor instructions prescribe SQLC query sources, but [book_search.go](../../internal/store/book_search.go), `user_list.go`, and `analytics.go` contain handwritten persistence code. [content_preferences.go](../../web/public/content_preferences.go) also constructs queries in the HTTP layer. | Document justified dynamic-query adapters and their testing requirements; move request-independent preference resolution behind an application service. Avoid forcing dynamic SQL into SQLC merely for uniformity. |
| Medium | **Frontend ownership has several competing homes.** API code lives in `src/api`, deprecated `src/public.api`, `src/features/api`, and feature-local directories. UI is distributed across `common/ui`, `components`, `islands`, and feature folders; `util`, `common/util`, and `lib` overlap conceptually. [BMBookAPI](../../web/frontend/src/api/bm/book.ts) uses a singleton while newer APIs use Effect services and other features use plain functions. | Publish one placement rule per responsibility, keep islands as entry/composition code, and migrate touched legacy APIs toward feature ownership. Give compatibility surfaces an explicit removal criterion. |
| Medium | **Runtime API contracts are optional despite strong type annotations.** [OLAPIResponse.ts](../../web/frontend/src/features/http-client/OLAPIResponse.ts) defaults to `Schema.Unknown` cast as the caller's generic type; legacy calls supply DTO types without schemas. It also decodes error bodies with the success schema, potentially masking the intended API error. `backend-types.ts` generation is configured but absent from `make codegen`/`check_generated`. | Require success schemas, decode error envelopes separately, and add DTO generation/freshness checks to the standard workflow. |
| Medium | **Large modules mix orchestration and presentation.** [routes_moderation_api.go](../../web/public/routes_moderation_api.go) is 999 lines; [UserModerationPage.tsx](../../web/frontend/src/features/moderation/components/UserModerationPage.tsx) is 820 and includes loaders, fetching, actions, and rendering. Size is a signal here because responsibilities also differ. | Split by workflow/resource and extract loaders, mutations, and repeated panels where ownership is clear. Avoid arbitrary file-size limits. |
| Medium | **Verification is available but incompletely connected.** `make check` covers generation, Go tests, and UI build, but tracked files contain no CI workflow. [package.json](../../package.json) exposes no test/lint/check-format commands despite installed tools. Three Node test scripts exist under `scripts` but are not invoked by `make check`; UI interaction and API-wrapper tests were not found. | Wire existing tests and lint commands into the standard check and CI. Prioritize authorization, workers, API decoding, and island lifecycle tests over snapshot coverage. |
| Low | **Global styles and boot imports broaden change impact.** [common/index.ts](../../web/frontend/src/common/index.ts) initializes many subsystems through import side effects; [style/index.ts](../../web/frontend/src/common/style/index.ts) loads shared components, home styles, and fonts globally. Multiple UI runtimes and styling mechanisms increase the number of places a change must be understood. | Keep shared tokens/primitives global, load feature styles with their entries where safe, and make subsystem initialization explicit and disposable. Preserve styles needed by server-rendered markup. |
| Low | **Repository and workflow documentation drift makes navigation harder.** Root-level `tmp.sql`, `up.sql`, and `populate.sql` sit beside the migration system without an obvious lifecycle. `.go_version` records Go 1.23.3, contributor docs say 1.24, and `go.mod` requests 1.27.0. `make main_watch` supplies `cmd/server/ui/dist` while Vite normally emits root `dist`. Older audit notes also describe superseded patterns such as Zod and unminified production output. | Consolidate tool versions and verify the development asset path. Document or archive one-off SQL/data tools, and clearly label historical audits rather than treating their snapshots as current findings. |

## Suggested sequence

1. Fix service authorization, worker lifecycle, and public error handling; add focused regression tests.
2. Unify index mapping and API response decoding; connect existing checks and generated DTO freshness to CI.
3. Consolidate frontend ownership and extract application workflows opportunistically, following the documented package boundaries.

Keep the current top-level Go layout. The largest gains come from consistent policies and ownership inside those folders, rather than introducing more architectural layers.
