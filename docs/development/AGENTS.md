# Development documentation

This guide applies to `docs/development`.

- Keep durable project workflows, architecture decisions, and contributor
  conventions here. Put temporary feature handoffs or implementation notes in
  the feature area when they cease to be broadly useful.
- Prefer short, task-oriented documents with concrete commands, file paths, and
  ownership boundaries.
- Update relevant documentation in the same change as a workflow or convention;
  remove obsolete advice rather than documenting competing paths.
- Link to canonical repository files and commands instead of duplicating long
  configuration or code snippets.
